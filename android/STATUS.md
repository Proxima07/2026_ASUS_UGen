## 尚未完善的位置

1. **鬧鐘與分享的完成驗證**：外部 App 是否最後保存沒有共通回傳協定，只回報交接。
2. **日曆不存在**：本版不建立新的 Calendar Account；沒有可寫／可提醒日曆時回報 `unsupported`。
3. **操作不確定**：保存 `preparing`／`claimed` 後，當機或期限過期時需人工查看手機；不自動重做。
4. **測試簽章**：Debug APK 供試用；正式版本須設定穩定的 release 簽章金鑰。
5. **自動配對**：使用原生畫面手動輸入 HTTPS 網址與一次性碼，尚無 QR Code。
6. **mTLS**：沒有配置；本版使用 HTTPS＋裝置 bearer，符合避免 API 明文傳輸的需求。
7. **Cloudflare Access**：本版未加入互動式 Access 登入流程；配置時需另外測試。
8. **WebView 短效 cookie**：由 WebView 的 App 沙盒管理；未以本程式額外 AES 加密 cookie 資料庫。
9. **手機筆記管理**：可保存、覆寫同 ID、列表與檢視；未提供刪除／匯出完整備份介面。
10. **多用戶與多設備管理**：由現有後端配對邊界處理，未提供管理面板。

## 驗收順序

1. 無配對碼與過期碼不得登入；HTTP、錯誤憑證不得連線。
   先用「檢查後端連線」確認原生網路；此步不能消耗碼。已被 Chrome 使用但尚未過期的碼仍應遭拒絕，APK 需另一組未用碼。
2. 「打給 XXX」先授權通訊錄、看到候選人，再開啟正確號碼。
3. 「明早七點鬧鐘」開啟目標時鐘並由使用者完成確認，檢查時鐘保存結果。
4. 日曆操作顯示日期、時間、時區與日曆帳號，確認後檢查事件及提醒。
5. 錄音與音訊匯入送私人後端，能顯示逐字稿、整理筆記與保存。
6. 保存到手機後斷網，仍可從 APK「手機筆記」閱讀。
7. 動作已執行但後端斷網時，「同步」只重送結果，不重複新增日曆或開啟電話。
8. 非指定來源及 iframe 不得呼叫原生橋接；停用裝置不能再存取。
9. web_v3 首頁說「幫我記下採買清單：雞蛋」→ 自動交接 → 原生確認 → 手機筆記可離線看到。
10. 再說「採買清單追加牛奶」→ 搜尋 → 原生確認更新 → 保留雞蛋並新增牛奶；多個同名筆記不得自動猜錯。

驗證結果應更新本文件後再宣稱完成。尚未取得目標實體手機進行完整端到端驗收。

## v3 已執行的驗證

- 最終來源 `assembleDebug` 成功，APK v2 簽章驗證通過。套件 `com.proxima.localassistant`、versionName 1.2、versionCode 3、minSdk 29、targetSdk 35；簽署憑證與 v1／v2 相同，具備覆蓋更新條件。僅有既有 `onBackPressed` 棄用警告，無編譯錯誤。
- 純 Kotlin／JVM 的錯誤分類及敏感資料自檢：22 項通過。涵蓋 HTTP 401／403／429、301／302／303／307／308 轉址、非 JSON、錯誤後端、TLS／憑證、DNS、逾時、無法建立連線、Keystore、Cookie 安裝階段、底線主機提示，以及原始例外／token 哨兵不得外洩。
- 唯讀審查確認：`GET /health` 不傳 token／配對碼；檢查與配對互斥；HTTPS、拒絕重新導向及原生橋接來源限制保留；登入失敗不清除已配對憑證。
- HTTP 回應讀取上限為 2 MiB，避免較大的合法筆記回覆遭過小上限拒絕，同時限制異常代理回覆。
- JDK 17 的 SNIHostName 自檢：含底線的樣本遭拒絕、對應連字號樣本通過。這是相容性線索，不是目標 Android 手機的 TLS 實測。

目標手機仍須確認：「檢查後端連線」實際結果、新配對碼、Keystore 保存與 WebView 登入。尚未確認截圖所示網址的失敗原因。
