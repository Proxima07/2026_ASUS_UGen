# backend_v4 功能狀態

更新日期：2026-10-12。Python 中樞第四版配合 web_v5 顯示語音階段與追蹤；APK 保留現有版本。手機行為尚未完成實機驗收。

| 項目 | 本版狀態 | 目前範圍與下一步 |
|---|---|---|
| OpenAI 相容 LLM | 已提供 | 設定自訂 URL／模型；實際模型輸出品質需在你的主機驗證 |
| 本地上下文與筆記 | 已提供 | SQLite 保存敏感欄位加密；不是向量搜尋／長期偏好學習的完整產品 |
| 身分與配對 | 已提供 | 一次性配對碼、裝置 token、session；web_v1／android_v1 有手動配對介面，尚無 QR code |
| 操作規劃與確認 | 已提供 | 操作白名單、參數檢查、確認／結果流程；日期或對象不明確需澄清 |
| 聯絡人搜尋／撥號 | 後端流程已提供 | android_v1 已實作通訊錄與 `ACTION_DIAL`，需實機驗證 |
| 鬧鐘 | 後端流程已提供 | 手機端時鐘 Intent 與各品牌相容性尚未驗證 |

| 語音自動指令 | 指令專用轉錄已提供 | 不先摘要，轉錄後由前端送 Agent；停頓偵測與手機前景需真機驗證 |
| 手機筆記優先 | 已提供 | 支援手機搜尋／取代／追加；只有明確失敗才改用平台，取消或不確定結果不回退 |

| 語音流程追蹤 | v4 新增 | 同裝置已完成 command job 與 chat 關聯；不取代身分驗證或執行防重複 |
| 選擇性文字除錯 | v4 新增 | LOG_COMMAND_TEXT 預設 false，true 才印最多 200 字元到終端機 |

## 驗收應分開看

1. **程式測試**：當前 75 項離線測試已通過，使用 fake／mock 模型驗證 API、操作防重複、裝置隔離、加密讀寫、請求容量、模型傳輸、手機筆記優先、指令轉錄、追蹤紀錄與網頁掛載。實測環境為 Python 3.12；尚未在 Pi、Windows 或實際模型上驗證。單獨解壓後端而未安裝網頁時，網頁掛載測試會略過。
2. **你的模型**：確認 OpenAI 相容程度、繁體中文日期解析與參數品質。
3. **實際部署**：Pi、模型主機、CA、Tunnel 與網域是否可連接。
4. **手機**：APK 權限、通訊錄、時鐘、日曆與第三方記事 App。

前一項通過，不會自動證明後三項已完成。展示時只宣稱已實際驗證的範圍。

本版單段話語規劃一個主意圖，通訊錄撥號與筆記修改可由確定性流程接續操作；不是任意多步工作流。平台筆記備援搜尋僅檢查最近 200 筆，未提供完整歷史分頁搜尋。多個可能對象仍需澄清。

## v4 已執行驗證

- 新增 7 項觀測／整合測試，全部 75 項後端測試通過。
- 驗證真實非同步工作先為 transcribing、完成後為 transcribed，command 模式沒有先摘要或自動觸發 Agent。
- 同裝置 source_job_id、command 用途、已完成狀態與逐字稿一致性驗證；同 key／同來源工作重送沿用 trace，模型只規劃一次。
- HTTP response ID 由伺服器產生；source job trace 不取用任意客戶端標頭。
- 預設不輸出內容或憑證；選擇輸出文字只允許最多 200 字元並 JSON 跳脫，不讓換行注入新事件。
- 上游錯誤、原始 exception／traceback、Cookie、token、配對碼及未知紀錄欄位不洩漏；未預期例外回安全 500。
- 程式版本為 4；實際 .env 不變、資料表無遷移。
- 與 web_v5 做本地整合：12 個新版執行資源正常供應，mock 音訊 → STT → source job 指令 → Agent trace 一致；模型一次、9 個階段事件可對照，預設內容及 token 不出現在紀錄。

尚未在使用者 PyCharm、實際 STT／LLM、公開 Tunnel 或手機上驗收。前端顯示 trace 可對照事件，但不能僅憑回應逾時判斷後端未收到請求。
