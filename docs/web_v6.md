# web_v6 多輪對話與倒數計時器

日期：2026-10-12。本包是 web_v5 的差異更新，搭配 backend_v5；手機倒數需要 android_v4。

## 本次問題

舊介面保留前面的文字泡泡，但每次 /chat 只送最新一句，後端模型也只收到該句。因而「明天早上十點的會議」後被問時長，再說「持續三十分鐘」時，模型會把它當作另一個新要求。

本版由後端保存已驗證的對話紀錄，前端只保存目前 conversation ID 與上一個 request ID。文字與語音使用同一個頁面對話，追問後能接續補條件；不把使用者提供的任意 assistant 歷史當作可信上下文。

## 介面與接續

| 對話 | 預期行為 |
|---|---|
| 明天十點開會；若被追問後補「持續 30 分鐘」 | 用先前的會議日期、時間接續日曆，不另問操作種類 |
| 剛剛的指令沒有必要條件 | 保留前文再追問，不臆測電話號碼或開始時間 |
| 按「新對話」 | 清除目前頁面對話關聯與訊息；下一句開始新的對話 |
| 幫我倒數 10 分鐘 | 顯示倒數長度，交給 APK 計時器確認 |

新對話不刪除手機筆記、平台筆記或已建立的日曆／計時器。前端不讀取歷史 action 來重播手機操作。後端仍要驗證裝置、操作內容及確認／執行憑證。

同頁只送一筆文字或語音 Agent 請求。請求、重試與回應綁定同一段對話及順序；新對話、登出與遲到回應不能把舊 conversation ID 放回新流程。結果不明時不自動重送手機動作；以畫面指示人工重試同一筆或開始新對話。

前端對話 ID 只在頁面記憶體，不將私人對話或憑證寫入 localStorage。重新整理／關閉頁面後以新對話開始；這版沒有跨頁歷史列表或永久偏好記憶介面。後端的歷史內容仍以既有加密方式保存。

## 更新

1. 在 backend_v4 上覆蓋 backend_v5，停止並重新啟動後端；保留現有 .env、STT／LLM 及既有 cloudflared。
2. 在 web_v5 上覆蓋 web_v6，檔案仍落在 local-assistant/web。
3. 由 android_v4 包內 APK 覆蓋更新；倒數需要新 APK 能力握手。
4. 從 https://2026-asus-ugen.aphelion.tw 強制重新整理，先測文字追問接續，再測計時器。

v5 的收聽、手動結束、真實 STT 階段、trace ID、錄音鎖修復與 v4 的缺檔提示均保留；全部執行資源使用一致 web-v6 revision。

## 驗證與界線

測試結果見 web/STATUS.md，API 與上下文上限見 docs/backend_v5.md。模型是否完整理解語意仍須實際本地模型驗證；本版不會因持有前文就略過原生確認。未支援原生計時器的環境不宣稱已完成手機倒數。

117 項 Node 測試與所有語法、DOM、同版資源、CSP／私人儲存檢查通過。本地後端整合驗證追問接續、重送一次、新對話隔離、13 個執行資源及 600 秒 timer action；尚未進行實際模型、瀏覽器或手機驗收。
