# web_v7 原生錄音、清楚反饋與筆記邊界

日期：2026-10-12。來源差異包套用在 web_v6，搭配 backend_v6／android_v5。

## 語音首頁

APK 內的語音首頁優先請原生錄音元件處理麥克風，不依賴 WebView 的 MediaRecorder。錄音先在手機私有暫存區形成完整音訊檔，按結束後才傳後端。轉錄完成後仍由後端 Agent 自動判斷操作，前端顯示逐字稿與實際處理狀態。

實際錄音開始後會顯示「收聽中」、持續跳動的經過時間，以及紅色的結束／取消控制。按麥克風或「結束錄音並送出」結束本次收聽；取消會捨棄尚未送出的音訊。等待權限、錄音與上傳是不同階段；權限未完成或初始化失敗不顯示假錄音狀態。

等待／收尾中的主麥克風可取消；瀏覽器與原生啟動均有15秒期限，遲到stream與callback釋放。原生ready包含身分，開始前核對expected user／device，不因存在橋接就跳過身分檢查。

重新點擊、離開畫面、新對話或登出會依本次錄音識別碼處理，舊 callback 不得重新鎖住介面或接到新對話。發生錯誤或逾時要回到可操作狀態，不能只留下「前一段錄音正在進行」。若已送出後端工作，取消本頁只停止後續處理，不宣稱已取消後端 STT 或手機已確認的動作。

一般 Chrome 網頁保留瀏覽器錄音路徑，也是在停止後上傳完整音訊檔；不需要 STT 服務支援即時串流。APK 原生錄音能力須透過受信任的橋接握手確認，不由網址或 UI 猜測。

## 進度與筆記

錄音／上傳／後端已收音訊／排隊／STT 轉錄／Agent 理解／等待手機確認分別呈現。可摺疊的除錯資訊保留 job、request、trace ID，方便和後端終端機事件對照。

手機記事本是手機安裝的記事本 App；前端顯示「已交給記事本，請在 App 內確認儲存」，不能把 Intent 交接顯示成已保存。日常語音不默默改用 APK 自建筆記或平台筆記；平台備忘錄是明確選擇的獨立位置。

錄音整理的草稿預設按「開啟手機記事本」直接建立交接動作，沒有中間平台副本；另有「保存到平台筆記」的明確選項。工具列表清楚標示「平台筆記」。

手機預設記事本沒有通用讀取／更新 API。查詢或追加既有手機筆記若不支援，畫面說明限制，不顯示另一個筆記區的內容冒充系統記事本。

平台筆記顯示依後端新授權邊界隔離，重新登入、登出或切換身分時須清除原頁面的筆記、選取狀態與遲到結果。這個清理不能取代後端權限檢查，實際內容仍由後端判斷是否屬於目前使用者與裝置。

2. 用 android_v5 內附 APK 更新安裝；原生錄音需要新 APK，單獨更新網頁不能改變舊 APK 的錄音實作。
3. 強制重新整理網頁／重新開啟 App，確認 bootstrap 不再顯示資源版本不一致。
4. 先確認錄音時鐘、紅色停止／取消與短錄音轉錄，再測不同配對裝置的平台筆記隔離及手機記事本交接。
