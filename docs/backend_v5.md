# backend_v5 多輪上下文、日曆預設與倒數

日期：2026-10-12。本包是 backend_v4 的差異更新，配合 web_v6、android_v4。

## 多輪對話

/chat 新增選填 conversation_id 與 parent_request_id。網頁第一句使用 conversation_id=new；後端產生 conv_ 開頭的隨機 ID，後續以該 ID 與上一個回覆的 request_id 接續。省略這些欄位的舊用戶端仍沿用單句行為及原本冪等上下文。

後端依裝置與使用者隔離對話，保存加密的請求關聯，從已保存 user／assistant 訊息及實際操作狀態組合上下文。歷史只作低權限參考，不是新的操作授權，不接受前端自造 system／assistant 指令。

同一段對話有順序檢查及鎖；parent 不是目前最後一筆時回 409，避免並行訊息混串。相同冪等鍵的重試沿用既有對話和 request，不再次建立模型操作。已完成、已取消或僅交接的歷史操作不能自動重播；一般「好／謝謝／收到」不會被當成重新執行命令。

歷史有訊息數與字數上限，避免無限增長。後端加密紀錄保留，但網頁頁面 ID 不寫入瀏覽器永久儲存；本版沒有跨頁恢復／歷史管理 UI。「新對話」只是開始新的範圍，不刪除既有筆記／日曆。

既有 .env 可追加以下設定；未填也會採用此預設：

```dotenv
CONVERSATION_MAX_MESSAGES=12
CONVERSATION_MAX_CHARS=16000
```

訊息數範圍 2–40，字數範圍 2000–48000。歷史以完整時間順序提供，受兩個預算限制；最新 user 指令與工具 Schema 另外計入輸入。log 的 history_messages／history_chars 可確認實際帶入數量。

## 日曆預設

開始日期與時間仍需要足夠資訊。可提供 duration_minutes（1–1440 的整數），後端計算 end；若同時給 end 而與時長矛盾會拒絕。未指定時長時預設 30 分鐘，提醒預設提前 10 分鐘；缺少標題使用中性的「行程」。模型可以從使用者已提供的「會議」等內容產生更精確標題。

採用的預設會由後端以 defaults_notice 告知，網頁及新 APK 確認畫面仍顯示實際開始／結束時間與提醒。這些預設不會猜聯絡人、電話號碼或未提供的開始時刻。

## 倒數計時器

新增 timer.create：

```json
{"duration_seconds":600,"label":"倒數計時"}
```

duration_seconds 是 1–86400 的整數。像「倒數 10 分鐘」「30 秒後提醒」「半小時後提醒看鍋子」可使用相對倒數；固定時刻仍採原鬧鐘／日曆規則。若前輪追問的是會議時長，「持續 30 分鐘」應接續該會議，不因出現時長就改成計時器。

後端建立待確認操作，由 APK 的時鐘介面處理。只能回報 opened／handed_off 等真實狀態，不能僅憑 Intent 交接宣稱計時器已開始或完成。既有操作收據、防重複、結果回報及原生確認仍保留。

## 更新與除錯

差異包依序覆蓋既有 backend_v4。啟動會自動建立對話所需的新表，保留舊請求、筆記與加密金鑰；來源包不覆蓋 .env 或 runtime 資料。停止並重新啟動後端後再更新網頁／APK。

延續 v4 的 INFO JSON log，觀察 conversation ID 與帶入歷史數量，同時可以追蹤音訊、STT、Agent、request ID。預設不輸出對話文字或憑證；LOG_COMMAND_TEXT 選擇開啟時只輸出有限長度的當句指令。

本地模型仍使用 .env 的 OpenAI 相容 URL／模型；上下文以標準 messages 傳入，不需更換模型服務。驗證與未完善位置見 backend/STATUS.md。
