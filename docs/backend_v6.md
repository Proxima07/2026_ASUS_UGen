# backend_v6 筆記隔離與手機預設記事本

日期：2026-10-12。來源差異包套用在 backend_v5，搭配 web_v7／android_v5。原本的本地模型、STT、上下文與計時器保留。

## 筆記存取修正

舊版配對裝置會被歸入共用的 `poc-user`，平台筆記又只依使用者查詢；不同配對裝置因此可能看到其他裝置建立的筆記。加密保存不能補足這個授權錯誤。

本版讓每張新配對碼預先由後端指定獨立使用者。未登入的配對請求不能指定使用者，裝置名稱也不能用來決定帳號。所有平台筆記的列表、單筆讀取、修改、刪除及衍生手機動作均須符合目前的使用者與原始建立裝置；猜到別人的筆記 ID 也不提供內容。

既有筆記保留原本的加密身分、裝置歸屬與金鑰，不刪除資料，也不將全部舊筆記分配給第一個新登入者。舊裝置的憑證仍可使用，但只能存取該裝置建立的筆記。重新配對會成為另一個裝置，不能自動繼承舊裝置的私人筆記；本版沒有帳號合併、跨裝置共享或搬移介面。

啟動會新增配對碼的使用者欄位與筆記裝置索引。舊版尚未兌換且仍有效的配對碼會取得獨立使用者；已消耗或過期碼仍不得重用。保留既有 `.env`、資料庫及 `data.key`，更新前先停止後端並做一致性備份。

啟動也隔離requests/actions/history中能用來源ID辨識的跨裝置或已刪除筆記快照，停止舊自建筆記待執行動作。沒有來源ID的歷史自由文字不能可靠歸屬，不宣稱已回溯清除所有暴露內容。DEFAULT_USER_ID仍能保留在舊.env，但新配對不使用共用身分；管理端--user-id也不略過裝置隔離。

修正會阻擋後續跨裝置存取，無法收回先前已顯示、截圖或被複製的筆記。若舊部署曾提供多人使用，應以先前可能已被讀取的資料範圍處理；本版沒有補造存取紀錄或宣稱未發生外洩。

## 手機記事本的真正含義

日常指令預設使用手機的記事本 App。後端建立 `notes.create_native` 操作，由 APK 取得完整且已驗證的內容，原生確認後開啟支援建立筆記的 App；若無直接支援，使用文字分享選擇器。使用者仍須在目標記事本內確認儲存。

「已開啟／已交接」不等於「記事本已儲存」。新流程不使用 APK 自建加密筆記區冒充手機預設記事本，也不默默另存一份平台筆記。缺少新 APK 能力、取消或交接不確定時，會顯示清楚狀態；使用者可以明確選擇平台備忘錄另行保存。

Android 沒有供所有廠牌記事本通用的內容搜尋、讀取與更新 API。因此本版可以協助建立／分享新筆記；不能通用地讀取或修改所有手機預設記事本。手機筆記查詢／更新指令會說明此限制，平台筆記仍可在明確選用平台時查詢與修改。

錄音整理的草稿透過POST /v1/notes/native-actions直接建立交接操作，不先偷偷建立平台筆記；若選「保存到平台筆記」，才使用平台保存路徑。

舊 APK 自建加密筆記資料保留，但新 APK 不再宣告其保存、搜尋或更新能力。後端為舊動作格式保留的相容路由，不代表新手機記事本流程已具備讀取／修改能力。

## 完整音訊檔與除錯

APK 錄音先形成私有暫存音訊檔，停止後才將完整檔案以 HTTPS 送至既有 `POST /v1/audio?purpose=command`。後端已支援此檔案 body；STT 仍接收完整音訊檔，不需要即時音訊串流介面。

上傳建立 job → queued → transcribing → transcribed → `/v1/chat` 的既有流程與 trace ID 保留。只有 STT 真正開始才顯示「轉錄中」；音訊或模型錯誤不宣稱已完成手機操作。`.env` 的 STT／LLM URL 與模型名稱不需要重新配置。

## 更新與驗證

1. 依原結構覆蓋 backend_v6、web_v7 的變動檔案。
2. 保留配置、資料庫與原始金鑰，停止並重新啟動後端；既有 cloudflared 不需要改成專案範例。
3. 用 android_v5 內附 APK 覆蓋安裝，重新開啟 App／網頁，確認資源版本一致。
4. 用兩張不同配對碼建立 A／B 裝置，確認筆記列表與直接 ID 操作都不能跨裝置取得資料，再測原生錄音與手機記事本。
