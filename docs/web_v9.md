# web_v9：修正登入核對停住與補足階段診斷

日期：2026-10-12。本包相對 web_v8，只更新網頁。保留 backend_v6、android_v6、既有 `.env`、配對資料與 cloudflared。

## 問題與證據

最新截圖顯示 APK「裝置驗證與 Cookie 後端驗證均成功」，HTTP200，使用者及裝置一致；網站卻持續停在「APK 配對已核對，正在驗證網頁登入 Cookie」，麥克風仍要求先配對。

這次證據已確認原生登入檢查通過，應繼續檢查網站自己的驗證與狀態切換。本版沒有將這個狀態當成配對資料失效，也不要求重新兌換配對碼。

本地程式檢查找到可重現的 web_v8 缺陷：成功的 /me 回覆會在清理舊狀態時更新 authGeneration；若清理元件拋出例外，catch 看到 generation 已變，會將同一次登入的失敗誤當成過期回覆跳過。此時網站沒有建立 identity，也沒有留下 connectionIssue，可一直顯示核對中。本地故障注入重現了與截圖相同的畫面狀態，但不能據此確認目標手機實際失敗的是哪個清理元件。

## 修正內容

登入驗證、身分核對、私人狀態清理與新身分啟用分開處理。同一次登入自行造成的狀態更新不再掩蓋後續例外；真正過期的請求仍不能覆蓋較新的登入。

任何清理失敗都先撤銷私人操作與錄音權限，依序嘗試所有清理；無法完成時隱藏私人主畫面，並顯示失敗階段，不留下無限「核對中」。重試成功清理、再核對Cookie身分後，才恢復主畫面。

「連線處理資訊」在失敗時自動展開，新增前端版本 web-v9 與目前階段：Cookie API驗證、身分核對、停止舊API／手機操作、清除對話／平台筆記／錄音草稿／語音，以及啟用已核對登入。若 /me 已成功，之後的前端失敗會保留HTTP200與追蹤ID。

| 安全錯誤碼 | 意義 | 下一步 |
|---|---|---|
| login_state_reset_failed | 舊私人狀態清理失敗；目前階段指出元件 | 提供階段與代碼，沿用配對資料重試 |
| login_ui_failed | 畫面或原生橋接登入狀態啟用失敗 | 提供階段與代碼，不當作Cookie拒絕 |
| web_session_timeout | 網站/me驗證超過20秒 | 檢查API／網路並使用既有重試入口 |

原API請求仍有15秒逾時，新增20秒驗證等待上限避免頁面流程無期限停住。連線診斷不列出cookie、token、配對碼、原始私人內容或例外堆疊。未登入時點麥克風會顯示目前連線警告，不再一律提示先配對。

失敗後可由既有重試入口恢復登入；重試不會重播對話、錄音或已執行手機動作。身分核對仍要求 Cookie 的 auth_kind=session，以及 user_id、device_id 與 APK 完全一致。

## 套用與驗收

1. 在現有 web_v8 上覆蓋 web_v9。ZIP 外層是 local-assistant，解壓到原 local-assistant 的上一層，確認更新的是後端 WEB_DIR 指向的 web。
2. 保留 backend_v6／android_v6、App 資料、`.env` 與既有 cloudflared。本次不需重裝 APK、重新配對或清快取。
3. 關閉後重新開啟 APK，或重新整理一般瀏覽器，載入 web-v9。
4. 成功時網站應切到已連接並允許麥克風。若失敗，展開「連線處理資訊」，提供其階段、安全錯誤碼、HTTP及request ID；不要提供cookie或token。

## 驗證與未完成

全部140項Node測試通過，包含6項本次新增回歸與原有134項。程式驗證包含清理元件失敗、登入等待期限、過期回覆與既有身分隔離回歸；使用隨附HTML的DOM模擬及故障注入，另經獨立程式審查。完整結果見 web/STATUS.md。

本地測試不是實際Chromium、目標手機WebView或公開Tunnel驗收。尚未確認截圖手機實際卡住的元件，也尚未在該手機驗證麥克風、STT與手機記事本。原有完整音檔上傳、原生確認與平台筆記隔離繼續保留。
