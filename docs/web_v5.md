# web_v5 手動結束錄音與階段回饋

日期：2026-10-12。本包為相對 web_v4 的差異更新，搭配 backend_v4；Android APK 沒有本次程式修改。

## 問題與修正

舊版將錄音秒數與停頓偵測一起放在 AudioContext.resume 之後。部分裝置的音訊分析器啟動未完成時，MediaRecorder 可能已在收音，畫面卻沒有秒數或音量回饋。

此外，原 stop 流程依賴非同步 stop 事件才釋放 CaptureCoordinator。若停止丟出錯誤、事件延遲或沒有回來，麥克風鎖可能保留；再次開始便顯示另一段錄音正在進行。此情況已以替身錄音器重現，尚未取得目標手機的原生錄音錯誤。

本版將錄音 session 的所有權、收尾與後續送出分開處理。手動結束先停止收音並釋放鎖，等待同一 session 的音訊收尾；收尾未完成時明確報錯，不上傳不完整音訊。舊 session 的遲到事件不得影響下一段錄音或重複送出。

## 畫面與操作

- 開始後顯示等待麥克風授權，再進入明確的「收聽中」、秒數與可用的音量回饋。
- 提供獨立「結束錄音並送出」，也保留點麥克風結束；按下後立即顯示收尾狀態，避免誤以為按鈕無效。
- 錄音階段取消會停止收音並捨棄未送出的音訊。
- 上傳、後端接收／排隊、STT 轉錄、辨識文字、等待 Agent 回應、手機確認及結果分開顯示。
- 上傳得到 queued 不等於 STT 已開始；只有後端工作狀態 transcribing 才顯示正在轉錄。
- /chat 為同步回應；等待時顯示送出／等待回應，不能僅憑 fetch 開始就宣稱後端已接收或模型已啟動。
- 除錯資訊可查看 audio job ID、指令 request ID 與可用 trace ID，對照後端終端機；資訊收進次要介面，不要求使用者選操作種類。

已送到後端的工作可能繼續完成。取消本頁後續處理、離開前景或重新載入，不能當作已取消 STT、模型或已確認的手機操作；本頁不再自動交接遲到結果。仍保留原生確認、防重複及僅處理當次前景語音的規則。

## 套用

1. 在原 backend_v3 上覆蓋 backend_v4，保留現有 .env、STT、模型與 Tunnel 設定，重新啟動後端。
2. 在原 web_v4 上覆蓋本包 web_v5；ZIP 解壓到現有 local-assistant 的上一層。
3. 開啟 https://2026-asus-ugen.aphelion.tw，強制重新整理；手機關閉舊頁面後再開啟。
4. 錄一段短指令，按「結束錄音並送出」，查看秒數停止、上傳及真實 STT 階段；展開除錯資訊對照後端 log。

v5 語音請求會附 source_job_id，讓 backend_v4 將轉錄工作與 Agent 指令對應到同一 trace。完整新流程需先更新後端；原有文字請求不必提供此欄位。

本版繼續使用 v4 的獨立載入檢查及一致版本資源，缺檔時保持停用並保留設定入口。驗證結果見 web/STATUS.md，已知界線與各版變更見 web/CHANGELOG.md。

## 驗證結果與界線

87 項 Node 測試通過，包含 28 項錄音所有權／停止競態邊界測試。JavaScript 語法、DOM、本地資源與完整模組圖檢查通過。與 backend_v4 的本地整合確認 12 個執行資源、mock STT／Agent 的同 trace、模型一次及 9 個可對照事件。

錄音收尾最多等 3 秒；沒有取得完整資料時明確失敗，不上傳該段。尚未在實際麥克風、Chrome／WebView、本地模型／轉錄服務與 Cloudflare 站台驗收。每個版本的測試結果不代表已確認你的手機音訊供應者。
